Push to your branch. Pallet takes it from there.

Pallet runs your web apps from a GitHub repository. Link a repo to an app, choose the branch that counts as production, and every push to it starts a build. Your team, their roles and your GitHub access all live in one organization.

From repository to running build in three steps

You do the first two once per app. After that, pushing to your production branch is all it takes.

1

Install the GitHub App

An admin installs Pallet on your GitHub account or organization and picks which repositories it can see. You can change that list on GitHub at any time.

2

Link a repository to an app

Choose the repo, the production branch and the folder your app lives in, such as apps/api in a monorepo. Pallet checks that you have push access on GitHub before it saves the link.

3

Push

Each push to the production branch starts a build. If you'd rather decide when, turn off auto build and start one by hand from the app page.

Your whole team, with the right amount of access

Invite people by email and give each one a role. Group them into teams, like Payments or Web, and assign apps to the team that owns them. You can belong to several organizations and switch between them from the sidebar.

RoleWhat they can do
ViewerSee apps, teams, members and repository links. Nothing changes.
DeveloperCreate and edit apps, change build settings and start builds.
AdminInvite people, manage teams, connect GitHub and link or unlink repositories.
OwnerEverything an admin can do, plus hand the organization to someone else or delete it.
